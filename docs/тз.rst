1. Общее описание
----------------------------------------------------------

Разрабатывается серверная часть веб-приложения для
бронирования рабочих мест в коворкинге.

**Ключевое условие:** готовые библиотеки и фреймворки
не используются. Используем только:

- HTTP-сервер
- Роутер (разбор URL)
- Шаблонизатор
- Интерфейс к базе данных
- Валидация данных

**База данных** — SQLite. Работа с ней — через свой
интерфейс (не через ORM).

По сути, создаётся **свой мини-фреймворк** (по принципу
WSGI: приходит запрос → сервер обрабатывает → возвращает
ответ), а поверх него — приложение «Коворкинг».

3.3. Сценарии (что нажимаем → что происходит)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**Сценарий 1. Регистрация**

1. Гость на главной нажимает «Регистрация».
2. Открывается форма ``/register`` (имя, email, пароль).
3. Заполняет, жмёт «Создать аккаунт».
4. Сервер (POST ``/register``):

   - проверяет, что email не занят;
   - проверяет формат полей;
   - хэширует пароль;
   - пишет пользователя в БД;
   - создаёт сессию.

5. Редирект на ``/workspaces`` — пользователь уже
   авторизован.

**Сценарий 2. Вход**

1. Гость нажимает «Войти».
2. Открывается форма ``/login`` (email, пароль).
3. Вводит, жмёт «Войти».
4. Сервер (POST ``/login``):

   - ищет пользователя по email;
   - сверяет хэш пароля;
   - создаёт сессию.

5. Редирект на ``/workspaces``.

**Сценарий 3. Бронирование места**

1. Пользователь на ``/workspaces`` видит список мест.
2. Нажимает «Забронировать» напротив нужного.
3. Открывается форма ``/bookings/new`` (место подставлено,
   выбор даты и времени).
4. Выбирает время, жмёт «Забронировать».
5. Сервер (POST ``/bookings/new``):

   - проверяет, авторизован ли;
   - проверяет, свободно ли место на это время;
   - если свободно → пишет бронь в БД → редирект
     на ``/bookings``;
   - если занято → возвращает форму с ошибкой
     «Это время занято».

6. На ``/bookings`` пользователь видит свою новую бронь.

**Сценарий 4. Отмена брони**

1. Пользователь на ``/bookings`` видит свои брони.
2. Нажимает «Отменить» напротив нужной.
3. Сервер (POST ``/bookings/cancel``):

   - проверяет, что бронь принадлежит этому пользователю;
   - удаляет бронь (или ставит статус «отменена»).

4. Редирект на ``/bookings`` — список обновился.

**Сценарий 5. Добавление места (админ)**

1. Админ на ``/admin/workspaces`` видит список мест
   и форму добавления.
2. Вводит название, описание, цену, жмёт «Добавить».
3. Сервер (POST ``/admin/workspaces``):

   - проверяет, что админ авторизован;
   - проверяет поля;
   - пишет место в БД.

4. Редирект на ``/admin/workspaces`` — место появилось
   в списке.

5. Стек технологий
----------------------------------------------------------

- **Язык:** Python 3.10+
- **Стандарт:** WSGI (PEP 3333)
- **WSGI-сервер:** ``wsgiref.simple_server``
- **База данных:** SQLite
- **Формат документации:** reStructuredText (``.rst``)

Разрешено использовать только стандартную библиотеку
Python.

Запрещено:

- Flask, Django, FastAPI, Bottle
- Jinja2, SQLAlchemy, Pydantic

----------------------------------------------------------
6. Планируемый результат
----------------------------------------------------------

Работающий веб-сервер, доступный по адресу
``http://localhost:8000``, который:

- отдаёт HTML-страницы по запросу;
- обрабатывает неизвестные адреса (404);
- в дальнейшем — поддерживает регистрацию, вход,
  бронирование и работу с БД.
