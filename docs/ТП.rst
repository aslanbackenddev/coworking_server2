==========================================================
Технический проект (ТП)
==========================================================

:Тема: Веб-приложение для бронирования
        рабочих мест в коворкинге


----------------------------------------------------------
1. Архитектура приложения
----------------------------------------------------------

Серверная часть построена по паттерну **Front Controller**.
Все входящие HTTP-запросы проходят через единую точку
входа — функцию ``application(environ, start_response)``
в файле ``app.py``.

**Структура проекта:**

.. code-block:: text

   coworking_server/
   ├── app.py               # Маршрутизатор (Front Controller)
   ├── run.py               # Запуск сервера
   ├── controllers/         # Контроллеры (бизнес-логика)
   │   ├── pages.py         # Отдача HTML-страниц
   │   ├── static.py        # Отдача CSS и изображений
   │   └── api.py           # Обработка API (JSON)
   ├── templates/           # HTML-шаблоны
   ├── static/              # Статика
   │   ├── css/style.css
   │   └── images/
   └── docs/                # Документация (ТЗ и ТП)

----------------------------------------------------------
2. Маршрутизация и контроллеры
----------------------------------------------------------

В файле ``app.py`` маршруты задаются в виде словаря
``ROUTES``. Ключом выступает технический URL-адрес,
а значением — функция-контроллер.

.. code-block:: python

   ROUTES = {
       "/": pages.index,
       "/login": pages.login,
       "/register": pages.register,
       "/workspaces": pages.workspaces,
       "/bookings": pages.bookings,
       "/bookings/new": pages.booking_new,
   }

**Принцип работы:**
Роутер читает ``environ['PATH_INFO']`` (путь) и
``environ['REQUEST_METHOD']`` (метод). Если путь найден
в словаре ``ROUTES``, вызывается соответствующая функция
из папки ``controllers``.

Каждый контроллер возвращает кортеж из трёх элементов:
``(тело_ответа, http_статус, mime_тип)``.

**API для отмены брони:**
Обрабатывается в ``api.py``. Принимает метод
``DELETE /bookings/<id>``, извлекает ID брони
и возвращает JSON-ответ с кодом ``200 OK``.

----------------------------------------------------------
3. Обработка статики и MIME-типы
----------------------------------------------------------

Для отдачи CSS и изображений используется контроллер
``static.serve_static``. Он определяет MIME-тип файла
по его расширению с помощью словаря ``MIME_TYPES``:

=================  ============================
Расширение         Content-Type
=================  ============================
``.css``           ``text/css; charset=utf-8``
``.png``           ``image/png``
``.jpg``           ``image/jpeg``
=================  ============================

Если файл текстовый (например, CSS), он читается в
кодировке UTF-8. Если бинарный (картинка) — читается
как поток байтов в режиме ``"rb"``.

----------------------------------------------------------
4. Формирование HTTP-ответов
----------------------------------------------------------

Функция ``make_response`` в ``app.py`` формирует заголовки
для каждого ответа:

- ``Content-Type`` — MIME-тип контента.
- ``Content-Length`` — размер тела ответа в байтах.
- ``Server: Coworking-WSGI/1.0`` — идентификатор сервера.
- ``Cache-Control: no-cache`` — отключает кэширование
  браузером.

Тело ответа всегда кодируется в байты (``.encode("utf-8")``),
как того требует стандарт WSGI.
